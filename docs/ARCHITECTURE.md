# Architecture and Implementation Specification

Status: Step 2 specification only  
Authority: `REFERENCE_AUDIT.md`, `INTERACTIONS.md`, and `ROUTES.md`  
Target: low-traffic private photography portfolio, statically generated and deployed to Cloudflare Pages

## 1. Decision summary

Use **Next.js App Router + TypeScript**, configured as a full static export with `output: 'export'` and `trailingSlash: true`. All known project routes are generated at build time from typed content. There is no runtime application server, database, API, authentication layer, CMS, or Server Action.

Use React for page composition and state ownership, GSAP with ScrollTrigger for choreographed motion, and one app-wide Lenis instance for desktop smooth scrolling. Keep photographic binaries out of Git: development reads mock assets from `/public/mock-media/`, while production resolves the same media IDs against an R2 custom domain.

This is the smallest architecture that preserves the audited route model, route metadata, persistent chrome, animation cleanup, content-driven case studies, and static deployment.

## 2. Why Next.js instead of a Vite React SPA

Both can deliver the visual design. Next.js is recommended because this portfolio has a finite, content-defined route graph and every case study needs its own canonical URL, metadata, and social preview.

| Criterion | Next.js static export | Vite React SPA |
|---|---|---|
| Static HTML per route | Native | Requires an added prerender/SSG layer |
| Project metadata and canonical tags | Route-level build-time API | Manual head management and prerender integration |
| Known dynamic project routes | `generateStaticParams()` | Router configuration plus prerender enumeration |
| Client transitions | Supported with persistent layouts | Supported |
| GSAP/Lenis reliability | Equivalent when isolated to client components | Equivalent |
| Cloudflare Pages | Direct `out/` deployment | Direct `dist/` deployment |
| Architectural overhead for this site | Low | Low initially, higher once SEO/prerendering is restored |

Next.js is not being selected for server features. It is being selected as a static site generator with a strong route and metadata model. If the project were truly one URL with no per-project metadata, Vite would be simpler; that is not the audited site.

## 3. Non-negotiable boundaries

- Step 1's 495 normalized route screenshots and 12 interaction captures are the visual baseline. Do not recapture unless a named gap blocks implementation.
- Do not copy the reference site's code, fonts, photography, video, Lottie files, or other proprietary assets.
- Roslindale and Mint Grotesk require commercial licenses. Use approved legal substitutes or separately licensed files supplied by the owner.
- Traditional Chinese and English are one art-directed composition, not alternate locale routes and not a language toggle.
- Motion index pages use posters and short previews only. Full films appear inside Motion case studies.
- The F-stop control is a persistent theme switch: desktop `F/24`, mobile `F/23`, alternate `F/1.4`.
- Internal route transitions use one full-screen color overlay and approximately 1,000 ms delayed navigation. Do not introduce FLIP or thumbnail-to-hero continuity.
- Breakpoints at 991, 767, and 479 px are first-class behavior boundaries.
- Code deployment and media deployment remain independent. A code release must not upload media, and a media release must not rebuild the site unless content or the manifest changes.

## 4. Success criteria

The architecture is ready for implementation when all of the following can be demonstrated:

1. Every route in the approved content files emits static HTML into `out/`.
2. No build output depends on a Node.js server, Pages Function, Worker, database, or runtime API.
3. All production media URLs are generated by one resolver from semantic media IDs and a build-time manifest.
4. Switching theme, navigating, and returning preserves the chosen F-stop state without a light/dark flash.
5. Page animation scopes are destroyed before navigation and recreated once after the next route is ready.
6. Each project page can reproduce its audited composition using the finite block union in `CONTENT_SCHEMA.md` without arbitrary JSX in content.
7. Desktop, tablet, mobile, touch, keyboard, and reduced-motion behavior all have explicit paths.
8. Cloudflare Pages can deploy only the `out/` directory and R2 can serve only the media bucket through a separate domain.

## 5. Runtime topology

```text
GitHub repository
  ├─ source, content, generated media manifest, mock assets
  └─ push / pull request
          ↓
Cloudflare Pages build
  ├─ validate content + manifest
  ├─ next build (static export)
  └─ publish out/ to portfolio.example.com

Original media outside Git
  └─ prepare-images / prepare-video (later media tooling)
          ↓
Cloudflare R2 bucket
  └─ media.example.com/{stable, versioned object keys}
```

At runtime, the browser loads HTML, CSS, JavaScript, icons, and local font files from Pages. Photographs, video posters, previews, and full films load from `media.example.com`. There is no browser call to an application API.

## 6. Rendering and routing model

### 6.1 Server/build-time boundary

Route `page.tsx` files remain Server Components. They import validated content and the generated media manifest at build time, define route metadata, and render static HTML. Only interactive leaves receive `'use client'`:

- persistent navigation and mobile menu;
- F-stop switch;
- route transition controller;
- smooth-scroll and animation providers;
- scroll-reactive sections;
- stills gallery rail;
- carousels;
- video playback controls.

This keeps content and metadata out of the client bundle while still permitting exact motion.

### 6.2 Route inventory

```text
/
/stills/
/stills/[slug]/
/motion/
/motion/[slug]/
/about/
/404.html
```

`generateStaticParams()` enumerates every Stills and Motion slug from validated content. Unknown slugs are never generated. The sitemap uses the same content arrays, which prevents the drift found in Step 1.

Set `trailingSlash: true` so each route becomes a directory with `index.html`, matching static-host semantics without redirect logic. Do not use middleware/proxy, request-dependent route handlers, cookies, draft mode, ISR, Server Actions, or default Next.js image optimization.

### 6.3 Route metadata

The root layout supplies the title template, default description, favicon, canonical base, default OG image, and theme colors. Project routes statically generate:

- title and description;
- canonical URL from `SITE_URL`;
- Open Graph and Twitter fields;
- project-specific 1200 × 630 social image from the media manifest;
- relevant image alt text.

Social images are prebuilt media objects, not runtime `ImageResponse` routes.

## 7. Application shell

The root layout owns stable elements that must survive route changes:

```text
RootLayout (build-time)
└─ ClientRuntime
   ├─ ThemeBoot + ThemeProvider
   ├─ RouteTransitionProvider
   ├─ SmoothScrollProvider
   ├─ PreloadCoordinator
   ├─ GlobalNavigation
   ├─ RouteTransitionOverlay
   └─ page content
```

The footer is route content rather than persistent shell content because its reveal and geometry differ by template. The navigation, theme switch, menu, transition overlay, and smooth-scroll instance are persistent.

### 7.1 Theme boot

An inline, nonce-free bootstrap snippet in `<head>` reads the `portfolio-theme` local-storage key and adds `theme-light` to `<html>` before the first paint. Its only job is avoiding theme flash. The React provider takes ownership after hydration.

Theme state values are `dark` and `light`. Labels are presentational and chosen with CSS by breakpoint:

- dark, desktop: `F/24`;
- dark, ≤991 px: `F/23`;
- light: `F/1.4`.

Theme colors are CSS custom properties. Components must consume semantic tokens rather than branching on theme in JavaScript.

## 8. Layout and responsive model

Use shared CSS custom properties for audited spacing, color, type scale, and chrome geometry. Use CSS Grid/Flexbox for layout; GSAP may animate transforms and opacity but must not own base layout.

```css
/* Behavioral bands, not an implementation snippet */
desktop:  min-width 992px
tablet:   768px–991px
mobile:   480px–767px
compact:  max-width 479px
```

Required characteristics:

- `>991`: inline navigation, 64 px page insets, desktop project stages and rails.
- `768–991`: collapsed navigation, 48 px insets, tablet media geometry.
- `480–767`: single-column case galleries, 32 px insets.
- `≤479`: 24 px insets, 48 px gallery rail, compact choreography and taller stages.

Viewport units should use `dvh`/`svh` fallbacks for mobile browser chrome. Full-height stages must not depend only on legacy `100vh`.

## 9. Typography architecture

Do not substitute fonts silently during implementation. Begin with a short visual bakeoff against the normalized screenshots and approve a legal stack before layout calibration.

Provisional open-license candidates:

| Role | Latin candidate | Traditional Chinese candidate | Notes |
|---|---|---|---|
| Editorial display | Bodoni Moda or Cormorant Garamond | Noto Serif TC | Select by width, contrast, and punctuation behavior |
| UI/body | IBM Plex Sans or Work Sans | Noto Sans TC | Medium and bold weights only |

Use locally hosted WOFF2 files through `next/font/local` after license verification. Subset Traditional Chinese fonts to the actual glyph inventory during the media/build preparation phase; never subset away glyphs referenced by content. Define `--font-display-latin`, `--font-display-tc`, `--font-body-latin`, and `--font-body-tc` so mixed-language runs can be explicitly art-directed.

Font loading is part of Level 1 preload. ScrollTrigger measurements occur only after the required font promises resolve.

## 10. Component boundaries

```text
components/
  chrome/       navigation, menu, F-stop, footer, transition overlay
  media/        MediaPicture, MediaVideo, PosterPreview, preload hints
  primitives/   SplitTextLines, MagneticLink, CopyEmail, section labels
  sections/     audited reusable compositions only
  stills/       index stage, case gallery, rail, Explore More
  motion/       index card, film hero, filmstrip, BTS, Explore More
  about/        portrait stage, story collage, credentials
```

Components own markup and accessible behavior. Animation modules receive refs and configuration; they do not query the whole document for anonymous class names. Content files hold data only and never import React components.

## 11. The five hardest interactions

| Rank | Interaction | Why it is hard | Implementation boundary |
|---:|---|---|---|
| 1 | Motion BTS long-scroll sequence | 5,400 px / 400 vh stages, pinned timing, responsive re-composition, heavy media | Dedicated GSAP timeline, breakpoint-specific measurements, preload gate |
| 2 | Stills case gallery + thumbnail rail | Active item detection, hash navigation, fixed rail, variable aspect ratios, Lenis coordination | CSS layout + IntersectionObserver + Lenis `scrollTo` + GSAP rail states |
| 3 | Motion hero playback | Poster/preview/full source handoff, autoplay policy, audio, pause state, reframe, bandwidth | Native video state machine + GSAP presentation; no third-party iframe |
| 4 | Global route transition lifecycle | Delayed navigation must coordinate overlay, cleanup, scroll reset, asset readiness, and rapid repeated clicks | Persistent React controller + Next router + GSAP overlay state machine |
| 5 | Persistent F-stop/theme switch | Pre-paint persistence, breakpoint-specific labels, one-second aperture motion, global token transition | Head bootstrap + React state + custom SVG/GSAP aperture animation |

## 12. Pure DOM + GSAP versus special implementation

### 12.1 Pure DOM/CSS + GSAP/ScrollTrigger

- home hero entrance and media reveal;
- editorial line reveals;
- paired still-image parallax;
- home Motion poster parallax;
- Stills and Motion index stage transforms;
- palette hover states;
- About portrait and collage movement;
- link, underline, arrow, and footer interactions;
- full-screen route overlay choreography;
- menu open/close choreography;
- aperture icon animation using an original inline SVG;
- filmstrip transforms once measurements are known.

No Three.js, WebGL, canvas renderer, GSAP Flip, or page-transition framework is justified by the audited behavior.

### 12.2 Special implementation beyond a GSAP timeline

- Gallery rail: IntersectionObserver and semantic hash targets are required for reliable active state and keyboard/deep-link behavior.
- Smooth scrolling: one Lenis instance must be synchronized with GSAP's ticker and ScrollTrigger.
- Explore More: use Splide 4 with the audited per-page settings instead of rebuilding drag, loop clones, accessibility, and pointer cancellation.
- Video: use the native HTMLMediaElement API with explicit poster → preview → full-film states, error fallback, and user-gesture audio activation.
- Preloading: a central coordinator must await image decoding and video readiness by priority level.
- Text reveals: split markup must remain accessible; the visual line wrappers are enhancement-only and must be rebuilt on meaningful resize/font changes.

## 13. Recommended dependencies

Required runtime dependencies only:

- `next`, `react`, `react-dom`, `typescript`;
- `gsap` with ScrollTrigger;
- `lenis`;
- `@splidejs/splide` for Explore More;
- `zod` for build-time content and manifest validation.

Developer dependencies may include ESLint, Prettier, Vitest, Testing Library, and Playwright. The future media toolchain may use Sharp and FFmpeg, but those do not belong in the browser bundle.

Do not add a global state library, CSS-in-JS runtime, UI component framework, CMS SDK, page-transition library, or animation abstraction layer.

## 15. Accessibility and input requirements

- Preserve native landmarks, headings, links, and buttons before animation enhancement.
- Mobile menu traps focus, closes on Escape, restores focus to its trigger, and sets `aria-expanded`.
- F-stop uses a real button with an accessible name that describes the destination state.
- Visual text splitting must not duplicate text in the accessibility tree.
- Gallery rail links use real fragment URLs; active state includes `aria-current`.
- Video controls remain keyboard operable and expose play/pause/mute state.
- Hover-only effects have focus-visible equivalents and are disabled when hover is unavailable.
- `prefers-reduced-motion: reduce` removes scrubbing, parallax, rotation, and long delays while preserving content and navigation.
- Theme contrast must be measured after final palette approval.

## 16. Performance budgets and rules

Initial targets for a mid-range mobile device on a cold connection:

- no layout shift caused by media; manifest dimensions reserve every box;
- one LCP candidate, explicitly preloaded;
- no full film downloaded from Home or Motion index;
- initial JavaScript target under 180 kB gzip excluding route-specific chunks, to be verified rather than assumed;
- no more than one global requestAnimationFrame driver;
- below-fold photography lazy-loaded with correct `sizes`;
- route-level animation modules loaded only on routes that use them;
- all long-lived media objects content-hashed and immutable.

The animation implementation must remain transform/opacity based. Layout reads happen before writes, and expensive measurements are cached until a breakpoint, font, or material viewport change invalidates them.

## 17. Verification gates for Step 3

1. **Static constraint:** inspect `out/`; each approved URL has HTML and there are no server bundles or Functions.
2. **Schema constraint:** invalid slug, duplicate block ID, missing media ID, absent dimensions, or illegal layout preset fails the build.
3. **Media constraint:** production build contains no reference photography and no `/mock-media/` URL.
4. **Lifecycle constraint:** repeated navigation does not increase active ScrollTriggers, RAF callbacks, observers, or media listeners.
5. **Responsive constraint:** visual regression snapshots cover 1920×1080, 1440×900, 1280×800, 393×852, and 390×844 plus the four breakpoint edges.
6. **Interaction constraint:** keyboard, touch, reduced motion, menu, theme persistence, gallery hashes, video fallback, and route overlays have end-to-end tests.
7. **Deployment constraint:** Pages preview works with `SITE_URL` and `NEXT_PUBLIC_MEDIA_BASE_URL`; R2 headers, CORS, cache, and byte-range playback are manually verified.

## 18. Major technical risks

1. **Typography metric drift:** an unapproved substitute changes line breaks and therefore scroll geometry throughout the site.
2. **Media not finalized:** unknown aspect ratios, focal points, video codecs, and durations block faithful layout tuning.
3. **Pinned sequence instability:** late media/font sizing or mobile browser viewport changes can invalidate BTS and filmstrip measurements.
4. **Route lifecycle leaks:** persistent layouts can leave old ScrollTriggers, observers, and video listeners alive if ownership is vague.
5. **Static-export drift:** adding a request-time Next.js feature later would silently break the chosen Pages-only topology.
6. **Cross-origin media configuration:** incorrect MIME, CORS, cache metadata, or video fast-start/range behavior can make valid files appear broken.

## 19. Inputs still required before coding for fidelity

- owner-approved route list, project order, and final copy in both languages;
- licensed final fonts or approval of the substitute bakeoff;
- owned photography and video masters, including legal usage confirmation;
- alt text, captions, credits, and copyright line;
- final site domain and media subdomain;
- approved dark/light palette values and confirmation that the audited `F/24` desktop / `F/23` mobile inconsistency is intentional;
- project-specific OG selections and crop/focal-point approval;
- Motion film audio policy, credits, poster frames, and intended full-film availability;
- email, social links, and any download links;
- explicit decision on whether a private portfolio means unlisted/public or access-controlled. Access control is not included in this architecture.

Implementation may scaffold with clearly marked mock content and mock media before these arrive, but visual calibration and production launch cannot be considered complete without them.
